# 通用 AI 网文创作流程规范（v1.1）

> 2026-08-17 · 这是整个项目的「宪法」。所有创作任务，一律按本流程走。
> 定位：**接收一个想法/简易大纲 → 向你确认问题 → 进入工作台正式生产**。通用、规范、可复用。

## 0. 四条总原则

0. **读感第一，终审在用户**：一切检测标准都是**动态参考**，不是及格线。唯一不变的门禁是"读起来怎么样"。**终审由用户负责**——用户是第一读者、最终裁决者；Agent 交付前用《读感终审清单》做**预审自检**，把能发现的问题先修掉，减少终审返工。**数值偏出 ≠ 返工，读感不对才返工。**
1. **结果导向**：AI 第一稿不可用 → 用「流水线 + 多轮质检」替代「一次生成」。
2. **编排确定性，判断在 agent**：流程用固定状态机（工序、台账、脚本）保证可查、可复评、可断点恢复；确定性脚本负责"报告"，LLM 负责"判断"。
3. **终审在用户**：题材、验收（过不过）、去留，用户拍板。

## 1. 设计依据：AI 的优势与劣势

### 1.1 AI 的优势
| 优势 | 用法 |
|---|---|
| 无限产能、不疲劳 | 多轮迭代不心疼 |
| 多方案并行 | 书名一次给 5 个、钩子给 3 个，让用户选 |
| 结构化输出强 | 圣经/人物卡/大纲/台账表格化 |
| 规则执行不偷懒 | 脚本 13 项检查、红线清零 |
| 知识面广 | 题材套路、典故、拆文随时调用 |

### 1.2 AI 的劣势（流程里补它）
| 劣势 | 根因 | 对策 |
|---|---|---|
| 第一稿平庸 | 优化"最可能的下一个词"=统计平均 | 多轮批判 + 去AI味 + 风格锚 |
| 长文本失忆 | 上下文窗口有限 | 圣经 + 台账 + 卷总结压缩 |
| 自夸不自批 | 生成者与审查者同源 | 双盲批判 + 强制挑刺(≥3处) + 评分卡 |
| 无爽感/笑点直觉 | 不理解读者主观感受 | 读感终审(人) |
| 自我重复 | 收敛到高频模式 | 神态复用/视线密度检查 |
| 需求理解偏差 | 单次对话信息不全 | **阶段A澄清** + 创作指令书签字 |

## 2. 流程总览（三阶段）

```
 ┌─────────────┐    ┌──────────────────────────────┐    ┌─────────────┐
 │ 阶段A 澄清   │ → │        阶段B 工作台            │ → │ 阶段C 验收   │
 │ (Intake)    │    │       (Production)            │    │ (Review)    │
 └─────────────┘    └──────────────────────────────┘    └─────────────┘
 想法 → 指令书         骨架 → 黄金三章 → 量产循环           反馈 → 迭代/归档
 (人拍板)             (人验收黄金三章)                     (人拍板去留)
```

## 3. 阶段A · 需求澄清

### 3.1 步骤
- **A1 接收**：用户给任意形态输入（一句话/脑洞/简易大纲/旧稿）。
- **A2 重述**：复述理解 + 显式列出假设，让用户纠错。
- **A3 澄清**：按问卷问 ≤4 个关键问题（选择项 + 自定义），已明确的跳过。
- **A4 指令书**：收敛成《创作指令书》交用户确认。
- **A5 开工**：确认 → 进阶段B。

### 3.2 澄清问卷（通用版）
1. 题材/子类型（必问）
2. 平台/读者（必问）
3. 篇幅/节奏：先试读 or 长连载（必问）
4. 核心钩子：有就给，没有 AI 出 3 个候选（必问）
5. 爽点偏好 + 禁区（必问）
6. 风格参考（选问）

## 4. 阶段B · 工作台

### 4.1 启动 runbook
1. 建目录 `novel-project/书名/`
2. 落《00-指令书.md》
3. `01-世界圣经.md`
4. `02-人物卡.md`
5. `03-大纲.md`
6. `04-伏笔台账.md`（喜剧加 `05-误会台账.md`）
7. `state.py init N --book <目录>`
8. 写黄金三章
9. **交用户验收**

### 4.2 目录结构
```
novel-project/书名/
├── 00-指令书.md
├── 01-世界圣经.md / 02-人物卡.md / 03-大纲.md
├── 04-伏笔台账.md  (05-误会台账.md 喜剧)
├── state.json / plotlines.json / misunderstandings.json
├── 章节/第001章-xxx.md
├── 质检/第001章-评分卡.md
└── 卷总结/卷1总结.md
```

### 4.3 黄金三章试点（止损点）
只写 3 章 + 完整设定，验收通过才量产。

### 4.4 逐章生产循环（9 工序）
```
① 情报包   从圣经+台账定向抽取
② 锁细纲   beat map：事件/冲突/爽点(≥1)/情绪起终点/章末钩子
③ 起草     ★一次写到目标区间(宁多勿少)
④ 双盲批判  评分卡 + 问题清单(强制≥3处)
⑤ 定向重写  只改问题段落
⑥ 去AI味   对黑名单+六原则清扫
⑦ 排版     长短句/段落镜头 + fix_quotes.py
⑧ 一致性   对照圣经+台账核对
⑨ 回灌     更新台账
```

## 5. 质检标准

### 5.1 红线（真·必改）
- 正文禁用词（对话/系统消息豁免）
- 金手指术语泄露给外人
- 解释句 / 上帝视角 / 说教句
- 设定冲突、时间线错乱

### 5.2 参考区间（动态，读感为准）
字数、句长、段落、密度、对话占比、比喻数、视线密度、神态复用——偏出 = 提醒，读感终审说了才算。

## 6. 人机分工
| 谁 | 干什么 |
|---|---|
| **用户** | **终审**：题材、验收（过不过）、去留、反馈 |
| **AI** | 其余全部 |
