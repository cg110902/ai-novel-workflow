# 流程复盘与修正（v1.1 · 2026-08-17）

> 核心结论：**读感第一、标准动态、流程适配 Agent 环境**。数值门槛只能是"体检报告"，不能是"及格线"。

## 一、这轮测试暴露的问题

### 1. 数值门禁在"打地鼠"（最严重）
反复打补丁，只为把碎短句 46% 压到 45%。这种 1% 级别的追逐，对读感毫无意义。
**根因**：把参考区间当成了及格线。

### 2. 首稿字数严重不足
三章初稿只有 668~1142 字（目标 2000~2500），后面全是"加法式补丁"。
**根因**：起草纪律缺失——没做到"一次写到目标区间"。

### 3. 脚本误报导致错误返工
- 对话占位符 `""` 被当碎短句统计
- 系统消息 `【】` 里的术语被判"金手指硬泄露"
- "如/似"单字误判成比喻
- 「到底还是」被误判成说教句

### 4. 双盲批判环节没留痕
只跑了脚本，没按流程产出"评分卡 + 问题清单"。

### 5. 引号排版问题
已补 `fix_quotes.py` 固化为排版固定动作。

## 三、"读感第一"怎么落地

1. **脚本 = 体检报告**（提示风险点），**读感终审 = 门诊**（决定治不治）
2. **数值偏出 = "这里多看一眼"，不是"返工"**
3. 唯一硬门禁 = 读感 + 你的验收
4. 检测标准是动态的

## 四、与开源库的根本区别

本流程是 **Agent 即引擎**：
- 无外部 LLM API，模型就是我
- 记忆 = 工作区文件（圣经/台账/卷总结/恢复包）
- 确定性检查 = 我在沙箱跑 python 脚本
- 交付物 = 好章节 + 可复用的流程资产
